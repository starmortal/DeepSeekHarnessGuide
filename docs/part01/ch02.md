## 本章目标

这一章不敲命令、不装环境，只把三件事讲清楚：**dsh 是什么、能干什么、和模型以及 Claude Code 这类工具有什么区别**。看完你就有底气进 CH 03 动手装了。

## dsh 是什么

一句话：dsh 是 DeepSeek 在 2026 年 8 月 13 日开源的 Agent 运行框架，命令名 `dsh`，全名 DeepSeek Harness，MIT 协议，官方定位是 developer preview（开发者预览版）。

官网首页就一句话——**Everything is a plugin（一切皆插件）**。官方给的等式：

> Agent = Model + Harness

翻译成大白话：**模型负责聪明，Harness 负责干活**。模型只会生成文字，Harness 让模型能读文件、敲命令、调 API、管上下文、做计划——把模型接进真实世界，任务才能真正做完。

## 先别把它当成什么

最容易踩的坑：把 dsh 当成一个"AI 编程助手"。

**不是。** Claude Code、Codex 是编码助手，它们是成品——工具、Skill、会话、沙箱全封装在一个壳里，墙不能拆、格局不能动。dsh 是"执行底座"：编码只是它预置的一套组合，你完全能用它拼出跟编程无关的 Agent。

另一个坑：**dsh 不是模型**。DeepSeek V4 flash（还有带视觉的 V4 flash vision exp）这类是模型，dsh 是让模型干活的"操作系统层"，它俩不是一回事。而且 dsh 里 DeepSeek 模型只是默认预置的一个插件，你完全可以换成别的模型。

## 四个关键词认识它

**1. 一切皆插件。** 模型、工具、Skill、会话、沙箱、存储、循环、调度、UI——每个能力都是插件（乐高），能换能删能加。

**2. 底层是 Cordis。** Cordis 内核管理插件的挂载、卸载和依赖。插件之间靠服务（services）和事件（events）协作，谁都能插一脚，谁都不是特权。

**3. 每次运行可追溯。** 模型看到的一切都会被写进追加式的会话日志：系统提示、推理、工具调用和结果、子代理调度、每一次上下文注入。在 Trajectory（轨迹）视图里按来源查。这意味着可观测、可审计、可复现——对研究和上生产很重要。

**4. 四种运行模式。** 别被名字吓到，它们不是四种引擎，而是官方预置的四套插件组合模板，你还能自定义新模式：

![四种运行模式（示意）](/assets/part01/runtime-modes.svg)

- **标准模式 Standard**：新手首选。完整代码 Agent 能力：文件编辑、Shell、文件/网页搜索、Skills、计划、目标、子代理、工作流，开箱即用。
- **代码模式 Code**：标准模式全部能力 + 工具以 SDK 方式暴露，模型写一段 TypeScript 程序一次编排多步操作。原本要五次模型往返的读取、搜索、筛选、并行调用，有机会压进一次程序执行，省 Token、降延迟。代价是依赖模型代码能力，调试更难，小白先别碰。
- **极简模式 Minimal**：只留持久化 bash + 文件编辑器。不是给你日常开发的，是用来跑"裸 Agent"基准测试——对比两个模型不挂任何花哨工具时谁底子强。
- **创造模式 Creator**：标准模式全部能力 + 多了一件事：能检查自己正在运行的 Cordis 环境，在内存里试验插件，创建新的 Agent 和插件，甚至改造它自己。

新手无脑选标准模式就够。等遇到大量重复工具调用、想压往返再切代码模式。日常开发别用极简模式，它缺东西会让你怀疑人生。

## 它适合谁，不适合谁

这几句是社区实测后的判断，不是官方口径。

**适合**：想研究插件机制、自己拼一套执行环境的开发者和 AI 爱好者；需要把 Agent 能力嵌进自有系统的团队——插件化是现成的底座；做 Agent 研究的人——轨迹功能天然适合做可复现实验；想用现成 Agent 处理日常杂活的个人用户——社区插件已经覆盖识图、读写 Office 文档（Excel/Word/PPT）、操作浏览器、多 Agent 组队这些方向，官方没做的坑，社区基本都填上了。

**现阶段要掂量一下的**：如果完全不想折腾插件、只想双击即用，dsh 还差点意思——官方默认只加载最小工具集（Shell、文件读写、代码编辑、网页搜索），识图、Office、浏览器这些都要自己装插件；而且官方明确警告是 developer preview、会有破坏性变更，每天都在更新。想省心就再等等，等默认能力补齐、生态理顺再上手也不晚。
