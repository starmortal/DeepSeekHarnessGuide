## 본장 목표

이 장에서는 어떤 조작도 가르치지 않습니다. 두 가지만 알려드립니다: 이 책의 읽는 법, 그리고 어떤 리듬으로 배울지. 먼저 자신에게 맞는 읽기 경로를 고르고, 3일 학습 계획에 따라가면 지도가 있어 당황하지 않습니다.

## 세 가지 읽기 경로

먼저 아래 그림을 보고 대략의 감을 잡으세요.

![세 가지 읽기 경로(개념도)](/assets/part00/reading-paths.svg)

### 경로 1: 초보자는 순서대로 읽기(추천)

**대상**: dsh가 처음이고, Agent를 한 번도 돌려본 적 없다.

**읽는 법**: CH 00부터 한 장씩 순서대로 읽습니다. PART 01(CH 02–08)을 한 번에 끝내고, 먼저 "돌릴 수 있다" 관문을 넘으세요. 이어서 CH 10 "핵심 서브시스템과 한 메시지의 흐름"을 읽고, 그 다음에 CH 09과 CH 11으로 돌아가면 "아, 이래서였구나" 하는 느낌이 옵니다.

**이 순서의 이유**: 앞쪽 장들은 실제 작업을 따라 구성되어 있어, 한 걸음이 다음 걸음의 발판 위에 놓입니다. 건너뛰면 막히고, 막힌 다음 돌아와 보충하는 쪽이 더 힘듭니다.

### 경로 2: 시나리오 직통

**대상**: 무엇을 할지 정해져 있어, 처음부터 읽고 싶지 않다.

**읽는 법**: 아래 표를 보고 바로 점프하세요.

| 목적 | 읽을 장 |
| --- | --- |
| 빨리 돌리기만 하고 싶다 | CH 03 → 05 → 06 |
| 아키텍처를 먼저 이해하고 싶다 | CH 09 → 11 |
| MCP 생태계에 연결하고 싶다 | CH 13 |
| 기존 플러그인을 찾아 설치해 쓰고 싶다 | CH 13 → 18 |
| Agent를 정해진 시간에 돌리고 싶다 | CH 16 |
| 로컬에 배포하고 싶다 | CH 17 |
| dsh로 PPT / 리포트 / 영상을 만들고 싶다 | CH 26 → 27 |
| 내 플러그인을 개발하고 싶다 | CH 19 → 21 → 22 |
| 운영 환경에 올리고 싶다 | CH 28 → 29 → 30 |

"시나리오 직통"으로 건너뛴 장에서 막히면 돌아와 보면 됩니다. 한 번에 다 읽는 사람은 없습니다. 부끄러운 일도 아닙니다.

### 경로 3: 필요한 곳만 깊게

**대상**: 이미 dsh를 돌릴 수 있고, 도구서로 쓰고 싶다.

**읽는 법**: 문제가 생기면 목차에서 해당 장을 찾아 부록과 함께 봅니다. 부록 A 용어집, 부록 B 명령어 치트시트, 부록 C 공식 문서 색인이 일상 3종 세트입니다. CH 08 트러블슈팅 치트시트는 단독 북마크 추천.

**특징**: 순서대로 읽을 필요 없음. 막히는 장만 펼치면 됩니다.

## 3일 학습 계획

집중해서 dsh를 처음부터 끝까지 한 번 훑고 싶다면, 아래 3일 계획을 그대로 따라 하세요. 하루 분량은 "읽으며 실습" 기준으로 설계되어 있어, 순수 문서 읽기가 아닙니다.

### Day 1: 돌리고, 직관을 세운다

**목표**: dsh를 설치해 돌리고, 무엇을 할 수 있는지 안다.

**읽기**: CH 00 → CH 08(PART 00 + PART 01)

**할 일**:
1. CH 03에서 Node.js와 dsh를 설치하고 Web UI를 띄운다
2. CH 05에서 화면에 익숙해지고, 워크스페이스를 고르고, 모델을 고르고, 첫 메시지를 보낸다
3. CH 06에서 headless를 한 번 돌려 "아무도 안 보고도 일한다"를 체험한다
4. CH 07에서 서드파티 모델(예: 로컬 모델 또는 다른 프로바이더의 API)을 연결한다
5. CH 08에서 에러가 나오면 트러블슈팅 흐름을 한 번 따라간다

**끝나면 할 수 있어야 할 것**: dsh 켜기, 메시지 보내기, headless 돌리기, 서드파티 모델 연결, 기본 에러 읽기.

### Day 2: 골격을 이해하고, 능력을 쌓는다

**목표**: "everything is a plugin"이 진짜 무슨 뜻인지 이해하고, 자주 쓰는 능력을 연결한다.

**읽기**: CH 09 → CH 17(PART 02 + PART 03)

**할 일**:
1. CH 09–11에서 플러그인 트리, 메시지 흐름, 세션과 궤적을 이해한다——이 세 장은 이론, 코드는 안 짜고 이해만
2. CH 12에서 도구 호출 파이프라인과 권한 승인을 이해한다
3. CH 13에서 MCP 서버(예: Firecrawl)를 연결해 Agent가 웹페이지를 가져오게 한다
4. CH 14에서 서브에이전트를 써서 "일을 남에게 시키기"를 체험한다
5. CH 15에서 Skill(예: AIHOT)을 설치해 Agent가 기존 능력을 쓰게 한다
6. CH 16에서 예약된 작업을 설정해 Agent가 매일 자동으로 돌게 한다
7. CH 17에서 로컬 모델을 연결해 "돈 안 들고 쓰기"를 체험한다

**끝나면 할 수 있어야 할 것**: dsh의 플러그인 아키텍처를 설명할 수 있고, MCP를 연결하고, 서브에이전트를 쓰고, Skill을 설치하고, 예약 작업을 설정하고, 로컬 모델을 연결할 수 있다.

### Day 3: 플러그인을 개발하고, 운영 환경에 올린다

**목표**: 내 플러그인을 직접 하나 쓰고, 배포와 운영을 안다.

**읽기**: CH 18 → CH 24(PART 04) + CH 28 → CH 30(PART 06)

**할 일**:
1. CH 18에서 플러그인 설치와 관리를 배운다
2. CH 19–22에서 네 종류 플러그인(최소 / 서비스 / 도구 / 훅)을 차례로 쓰며 각각 돌린다
3. CH 23에서 UI 플러그인을 써서 설정 페이지에 탭을 추가한다
4. CH 24에서 모델 어댑터를 이해한다(선택, 플러그인 개발 안 하면 건너뛰기 가능)
5. CH 28에서 Docker로 dsh를 서버에 배포하고 도메인을 묶어 HTTPS를 설정한다
6. CH 29에서 보안 체크리스트를 훑어 권한과 키 설정에 과부족이 없는지 확인한다
7. CH 30에서 궤적 읽기, 컨텍스트 관리, 비용 통제를 배운다

**끝나면 할 수 있어야 할 것**: 돌아가는 플러그인을 쓰고, 서버에 배포하고, 보안과 비용을 관리할 수 있다.

## 세 경로의 공통 출발점

어떤 경로를 가든, 먼저 10분만 CH 00을 읽으세요. 직관 3개뿐, 조작은 없지만 이후 모든 장의 토대입니다: **Agent = Model + Harness, everything is a plugin, 왜 지금인가**.
