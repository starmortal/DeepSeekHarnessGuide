## Objetivo do capítulo

Este capítulo não ensina nenhuma operação. Ele diz apenas duas coisas: como ler este livro, e a que ritmo aprender. Escolha primeiro uma rota de aprendizagem que combine com você, e depois siga o plano de três dias — com um mapa, você não vai se perder.

## Três rotas de leitura

Dê uma olhada neste diagrama primeiro, para ter uma ideia aproximada:

![Três rotas de leitura (ilustração)](/assets/part00/reading-paths.svg)

### Rota 1: leitura sequencial para iniciantes (recomendada)

**Para quem é**: primeira vez com o dsh, nunca executou um Agent.

**Como ler**: comece pelo CH 00 e avance capítulo a capítulo. Termine a PARTE 01 (CH 02–07) de uma vez — passe primeiro a barreira do "já funciona". Em seguida leia CH 09 "Subsistemas centrais e o fluxo de uma mensagem", e só depois volte a CH 08 e CH 10. Você vai ter a sensação de "agora eu entendo".

**Por que essa ordem**: os primeiros capítulos estão organizados em torno de tarefas reais; cada passo se apoia exatamente no que o próximo precisa. Pular etapas trava, e destravar depois custa mais.

### Rota 2: salto direto por cenário

**Para quem é**: você já sabe o que quer fazer, não quer ler desde o início.

**Como ler**: pule direto com esta tabela:

| Seu objetivo | Ler isto |
| --- | --- |
| Só quero colocar de pé | CH 03 → 04 → 05 |
| Quero entender a arquitetura antes de tocar | CH 08 → 10 |
| Quero me conectar ao ecossistema MCP | CH 12 |
| Quero encontrar plugins prontos e instalar | CH 12 → 17 |
| Quero que o Agent trabalhe em horários programados | CH 15 |
| Quero fazer deploy local | CH 16 |
| Quero usar o dsh para fazer PPT / relatórios / vídeos | CH 25 → 26 |
| Quero desenvolver meus próprios plugins | CH 18 → 20 → 21 |
| Quero colocar em produção | CH 27 → 28 → 29 |

Os capítulos que você pular com "salto por cenário" podem ser revisitados se travar — não tem problema. Ninguém termina de primeira.

### Rota 3: aprofundar sob demanda

**Para quem é**: já consegue executar o dsh, usa este livro como referência.

**Como ler**: quando aparecer um problema, olhe o índice e pule para o capítulo correspondente, combinado com os apêndices. Apêndice A (Glossário), Apêndice B (Chuleta de comandos), Apêndice C (Índice de documentação oficial) são o trio diário. CH 07 (Chuleta de troubleshooting) vale favoritar à parte.

**Característica**: não precisa ler em ordem; quando travar num capítulo, abra-o.

## Plano de aprendizagem de três dias

Se você quer percorrer o dsh do começo ao fim num bloco concentrado, o plano de três dias abaixo pode ser seguido tal qual. A carga diária está dimensionada para "ler enquanto faz" — não é só ler documento.

### Dia 1: colocar de pé, construir intuição

**Objetivo**: instalar o dsh, colocá-lo de pé e saber o que ele pode fazer.

**Ler**: CH 00 → CH 07 (PARTE 00 + PARTE 01)

**Fazer**:
1. CH 03: instale o Node.js e o dsh, abra a Web UI
2. CH 04: familiarize-se com a interface — escolha workspace, modelo, envie a primeira mensagem
3. CH 05: execute uma tarefa headless uma vez, experimente "trabalha sem ninguém olhando"
4. CH 06: conecte um modelo de terceiros (por exemplo, um modelo local ou a API de outro provedor)
5. CH 07: quando aparecer um erro, percorra o fluxo de troubleshooting

**Ao final você deve ser capaz de**: abrir o dsh, enviar mensagens, executar headless, conectar um modelo de terceiros, ler erros básicos.

### Dia 2: entender o esqueleto, montar capacidades

**Objetivo**: entender o que realmente significa "everything is a plugin", e conectar as capacidades habituais.

**Ler**: CH 08 → CH 16 (PARTE 02 + PARTE 03)

**Fazer**:
1. CH 08–10: entenda a árvore de plugins, o fluxo de mensagens, as sessões e a trajectory — estes três são teoria, sem código, só compreensão
2. CH 11: entenda o pipeline de chamadas de ferramentas e as aprovações de permissão
3. CH 12: conecte um servidor MCP (p. ex. Firecrawl) para que o Agent possa capturar páginas web
4. CH 13: experimente um subagent, sinta "delegar trabalho a outros"
5. CH 14: instale um Skill (p. ex. AIHOT) para que o Agent use capacidades já prontas
6. CH 15: configure uma tarefa programada para o Agent rodar todo dia automaticamente
7. CH 16: conecte um modelo local, experimente "usar sem gastar"

**Ao final você deve ser capaz de**: explicar a arquitetura de plugins do dsh, conectar MCP, usar subagents, instalar Skills, configurar tarefas programadas e conectar um modelo local.

### Dia 3: desenvolver plugins, colocar em produção

**Objetivo**: escrever um plugin próprio, e saber como fazer deploy e operar.

**Ler**: CH 17 → CH 23 (PARTE 04) + CH 27 → CH 29 (PARTE 06)

**Fazer**:
1. CH 17: aprenda a instalar e gerenciar plugins
2. CH 18–21: escreva quatro plugins acompanhando o livro — mínimo, serviço, ferramenta, hook — e coloque cada um para rodar
3. CH 22: escreva um plugin de UI e adicione uma aba na página de ajustes
4. CH 23: entenda os adaptadores de modelo (opcional; pule se não for desenvolver plugins)
5. CH 27: use Docker para fazer deploy do dsh num servidor, associe um domínio e configure HTTPS
6. CH 28: percorra a checklist de segurança, confirme permissões e credenciais
7. CH 29: aprenda a ler trajectories, gerenciar contexto, controlar custo

**Ao final você deve ser capaz de**: escrever um plugin que rode, fazer deploy num servidor, e gerenciar segurança e custo.

## Ponto de partida comum das três rotas

Independente da rota escolhida, dedique primeiro dez minutos ao CH 00. São só três intuições, sem operações, e ainda assim é a base de tudo o que vem depois: **Agent = Model + Harness, everything is a plugin, por que agora**.

## O que você aprendeu neste capítulo

Você passa se conseguir completar os itens abaixo:

- [ ] Citar as três formas de ler, e saber qual rota tomar quem se aproxima do dsh pela primeira vez
- [ ] Indicar a correspondência objetivo → capítulo do "salto por cenário" (pelo menos: conexão MCP → CH 12, desenvolvimento de plugins → CH 18)
- [ ] Saber o que ler e o que fazer cada dia do plano de três dias
- [ ] Saber que, seja qual for a rota, é preciso ler CH 00 antes para assentar a base
