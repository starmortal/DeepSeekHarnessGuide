## Objetivo do Capítulo

Este capítulo não tem comandos nem ambiente para configurar. Ele esclarece três coisas: **o que é o dsh, o que ele pode fazer e como ele se diferencia de um modelo ou de ferramentas como Claude Code**. Ao final, você estará pronto para instalá-lo no CH 03.

## O que é o dsh

Em uma linha: o dsh é o framework de runtime Agent que a DeepSeek tornou open-source em 13 de agosto de 2026. O nome do comando é `dsh`, o nome completo é DeepSeek Harness, a licença é MIT e o posicionamento oficial é developer preview.

A página inicial diz em uma única linha — **Everything is a plugin** (Tudo é um plugin). A equação oficial:

> Agent = Model + Harness

Em palavras simples: **o modelo pensa, o Harness faz o trabalho.** Um modelo apenas gera texto; o Harness é o que permite a um modelo ler arquivos, executar comandos, chamar APIs, gerenciar contexto e planejar — conectando o modelo ao mundo real para que as tarefas possam realmente ser concluídas.

## Não Confunda Com

A armadilha mais fácil: tratar o dsh como "um assistente de código de IA".

**Não é.** Claude Code, Codex — esses são assistentes de código. São produtos acabados: ferramentas, Skills, sessões e sandbox estão todos envolvidos em uma casca; a parede não pode ser derrubada, o layout não pode ser alterado. O dsh é um "substrato de execução": programação é apenas uma combinação predefinida, e você pode montar completamente Agents não relacionados a programação.

Outra armadilha: **o dsh não é um modelo.** DeepSeek V4 flash (e a V4 flash vision exp habilitada para visão) — esses são modelos. O dsh é a "camada de sistema operacional" que permite ao modelo trabalhar; eles não são a mesma coisa. E no dsh, o modelo DeepSeek é apenas o plugin padrão pré-instalado — você pode substituí-lo por qualquer outro modelo.

## Quatro Palavras-Chave Para Conhecê-lo

**1. Tudo é um plugin.** Modelo, ferramentas, Skill, sessão, sandbox, armazenamento, loop, agendador, UI — cada capacidade é um plugin (uma peça de Lego), e você pode trocar, excluir ou adicionar.

**2. A camada base é o Cordis.** O kernel Cordis gerencia a montagem, desmontagem e dependências dos plugins. Os plugins se coordenam por meio de serviços e eventos; qualquer um pode entrar, ninguém é privilegiado.

**3. Cada execução é rastreável.** Tudo o que o modelo vê é gravado em um log de sessão append-only: system prompts, raciocínio, chamadas de ferramentas e resultados, agendamento de subagents, cada injeção de contexto. Navegue por origem na visualização Trajectory. Isso significa observável, auditável, reproduzível — importante para pesquisa e produção.

**4. Quatro modos de runtime.** Não se assuste com os nomes: não são quatro engines, mas quatro templates oficiais predefinidos de combinação de plugins — e você pode definir novos por conta própria:

![Quatro modos de runtime (ilustração)](/assets/part01/runtime-modes.svg)

- **Standard**: o padrão para novos usuários. Capacidades completas de Agent de código: edição de arquivos, Shell, busca de arquivo/web, Skills, planos, objetivos, subagents, workflows. Pronto para uso imediato.
- **Code**: tudo o que o Standard tem, mais ferramentas expostas via SDK para que o modelo possa escrever um programa TypeScript e orquestrar várias etapas em uma única passagem. Cinco roundtrips de modelo do tipo "ler, buscar, filtrar, chamar em paralelo" podem potencialmente colapsar em uma única execução de programa, economizando tokens e reduzindo latência. O custo é a dependência da capacidade de codificação do modelo e a dificuldade de depuração; iniciantes devem ficar longe.
- **Minimal**: apenas bash persistente + um editor de arquivos. Não é para desenvolvimento diário — é para rodar benchmarks de "Agent nu" para comparar a força bruta de dois modelos sem ferramentas sofisticadas.
- **Creator**: tudo o que o Standard tem, mais um extra: pode inspecionar o ambiente Cordis em execução, experimentar plugins na memória, criar novos Agents e plugins, e até mesmo modificar a si mesmo.

Novatos devem escolher Standard. Mude para Code quando enfrentar chamadas de ferramentas repetitivas pesadas e quiser comprimir roundtrips. Não use Minimal para o trabalho diário — faltam peças e fará você questionar suas escolhas de vida.

## Para Quem É, e Para Quem Não É

Essas linhas são a avaliação da comunidade a partir de testes reais, não a posição oficial.

**Adequado para**: desenvolvedores e entusiastas de IA que querem estudar o mecanismo de plugins e montar seu próprio ambiente de execução; equipes que precisam incorporar capacidades Agent em seus próprios sistemas — o modelo de plugin é um substrato pronto; pesquisadores de Agent — o recurso de trajectory é naturalmente adequado para experimentos reproduzíveis; usuários individuais que querem usar Agents prontos para tarefas diárias — plugins da comunidade já cobrem reconhecimento de imagem, leitura/escrita de documentos Office (Excel/Word/PPT), automação de navegador, equipes multi-Agent, etc. As lacunas que a equipe oficial não preencheu, a comunidade já fechou em sua maioria.

**Pense duas vezes se**: você não quer mexer com plugins e apenas quer clicar-duplo-e-ir — o dsh ainda não está lá. O padrão oficial carrega apenas o conjunto mínimo de ferramentas (Shell, leitura/escrita de arquivos, edição de código, busca web); para reconhecimento de imagem, Office e automação de navegador você precisa instalar plugins por conta própria. E a equipe oficial adverte explicitamente que isso é um developer preview com breaking changes, atualizado diariamente. Se você quer paz de espírito, espere até que as capacidades padrão sejam completas e o ecossistema se estabilize.
