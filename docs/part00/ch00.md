## 本章目标

写这一章之前，我其实纠结了很久要不要花时间搞懂 dsh。市面上的 Agent 框架太多了，多一个少一个好像无所谓。但真正上手之后我发现，dsh 跟它们不是一类东西——它不是又一个"开箱即用的 Agent 工具"，而是一套**让你自己拼装 Agent 的套件**。

这一章不教你敲命令，先帮你建立三个直觉。搞清楚这三件事，后面每一章你都会知道自己在干什么：

1. **Agent 到底是什么**——官方给了一句话公式：`Agent = Model + Harness`
2. **为什么说"一切皆插件"**——这就是"乐高"两个字的意思
3. **为什么偏偏是现在**——2026 年 8 月 13 日开源后发生了什么

## 动手

### 第一步：把公式抄下来

DeepSeek 官方把 dsh 的定位写成一句话：

```
Agent = Model + Harness
```

Model 就是大模型本身（DeepSeek-V4 全系也好、第三方模型也好），它只负责"想"。Harness 是除了模型之外的所有东西：工具、提示词、记忆、上下文管理、任务规划、多 Agent 协作、MCP、Skill……也就是让一个模型真正**干成事**的那套壳。

打个比方：**模型是一匹好马，Harness 是缰绳和马具**。没有马具的马再快也只能原地打转；套上马具，才能指哪打哪。

一句话：**模型负责聪明，Harness 负责干活。**

### 第二步：理解"乐高"

dsh 官方 README 的开头第一句是：

> It uses an architecture where **everything is a plugin**

一切皆插件。翻译成人话：模型适配器、工具注册表、会话日志、Agent 循环、UI、记忆、调度——每一个都是独立的插件块，你可以在配置里选、换、删、加，不用改一行框架源码。

它底层跑在一个叫 **Cordis** 的 TypeScript 插件系统上（官方说这套系统打磨了四年）。dsh 一行命令的背后，是一棵由 90 多个插件叠成的"插件树"。下面这张图把它的结构画出来了：

![dsh 的插件树架构（示意）](/assets/part00/dsh-arch.svg)

看这张图，重点就两件事：

1. **底座是 Cordis**——所有插件都长在它上面，由它统一管理；
2. **连 Agent 主循环都是插件**——就是中间那个荧光黄的方块。这是最颠覆的一点：dsh **没有核心、没有特权路径**。你想换掉默认的"思考-执行"循环？那不是一个重写框架的大工程，只是换一个插件。

这就是"乐高"：底座是固定的，但你能拼出任何形状。想换模型？换一个插件。想加工具？装一个插件。想换界面？装一个皮肤插件。所以叫"Agent 的乐高时代"。

### 第三步：看看"为什么是现在"

2026 年 8 月 13 日晚，`deepseek-ai` 组织下一个新仓库悄然公开，仓库描述只有一句话——"Everything is a Plugin."。没有发布会，没有长文宣传，README 里甚至直接警告"未来会有破坏兼容性的变更"。

然后数据就开始离谱了（都是当时媒体实测报道的数字，不是官方吹的）：

- 开源 **24 小时**，star 破 **4.6 万**（Hacker News 冲到 top1）
- 开源 **48 小时**，star 破 **10 万**
- 上线 **3 天**，star 超 **13 万**，Fork 近 1.4 万
- 插件生态：开源当晚实测收录 **288** 个插件仓库 → 几天内打上 `dsh-plugin` 标签的仓库超 **1000** 个 → 5 天涨到 **6000+** 个

为什么这么炸？因为在此之前，Agent 的"身体能力"——接文件、跑终端、调工具、组织上下文——一直被 Claude Code、OpenAI Codex 这些**闭源产品焊死**。你想定制？要么用厂商给的插件机制（受限于它），要么自己从头造轮子。DeepSeek 这次把整层开源了，还把它拆成了乐高积木。
