## アーキテクチャ

| 用語 | 一行説明 |
|---|---|
| **Cordis** | dsh のベース層にあるプラグインフレームワーク。サービス登録、型付きイベント、可逆副作用の三つのプリミティブを提供し、dsh のすべての機能はこの上で動作します |
| **Plugin（プラグイン）** | dsh の最小機能単位。`apply(ctx)` 関数を export するモジュールです。起動時にロードされ、ctx 経由でツール登録、イベント購読、サービス提供を行います |
| **Bundle（バンドル）** | プラグインの配布形式である npm パッケージで、ランタイムにどのプラグインと設定をもたらすかを宣言します。プラグインのインストールは本質的に Bundle のインストールです |
| **Profile（プロファイル）** | プラグイン群の組み合わせレシピで、「このプラグインネットワークがどう見えるか」を決めます。web、headless はいずれもプロファイルで、`$DSH_HOME/profiles/` 配下に保存されます |
| **Context（ctx）** | プラグインがロード時に受け取るコンテキストオブジェクトで、すべてを担います。ツール登録、サービス呼び出し、イベント購読、設定の読み書き、すべて ctx に依存します |
| **Service（サービス）** | プラグインが ctx 経由で提供する再利用可能な機能で、他のプラグインから呼び出せます。例：セッションサービス、ツール登録サービス |
| **Event（イベント）** | プラグイン間の通信方式で、pub/sub パターンです。例えばツール実行前に `tools/pre-execute` イベントが発火し、他のプラグインが購読して割り込めます |
| **Effect（エフェクト）** | プラグインがランタイムに加える変更（ツール登録、設定追加など）。プラグインのアンロード時には逆順に取り消され、綺麗に復元されます |
| **Seam（シーム）** | プラグイン間のインターフェース規約。あるプラグインが「私はこの能力が必要」と宣言し、別のプラグインが「私はこの能力を持つ」を提供すれば、システムが自動でマッチングします |

## ランタイム

| 用語 | 一行説明 |
|---|---|
| **Agent Loop** | 「考える → ツールを呼ぶ → 結果をみる → 再び考える」の反復ループで、タスク完了または終了条件到達まで続きます。Agent とチャットボットの本質的な違いはこの点にあります |
| **Turn** | ユーザーがメッセージを送ってから、Agent が最終回答を返すまでを 1 ターンとします。ターン内部では複数のツール呼び出しが起こり得ます |
| **Step** | Agent Loop における 1 回の反復で、モデル呼び出しかツール呼び出しのいずれかです。1 ターン = 複数の step |
| **Session** | 1 回の完全な対話コンテキスト。ワークスペースに紐づき、永続化されます。dsh を閉じて再度開いても続きから再開できます |
| **Trajectory（軌跡）** | セッションの完全な実行記録。システムプロンプト、モデルリクエスト、ツール呼び出し、サブエージェントのスケジューリングがすべて時系列で記録されます |
| **Headless（ヘッドレス）** | インターフェースを必要としない実行方式で、1 コマンドでタスクを実行して終了します。自動化、CI/CD、定時タスクに適しています |
| **Web UI** | ブラウザの対話型インターフェース。`dsh web` で起動し、デフォルトアドレスは `http://127.0.0.1:3080` |
| **Fork（フォーク）** | セッションの特定履歴ノードから新しい分岐を開き、元のセッションはそのまま残します。「別のやり方を試す」用途に向きます |
| **Compaction（コンパクション）** | 過去の対話を要約にまとめて元の履歴と置き換え、コンテキスト領域を解放します。`/compact` コマンドで手動トリガーできます |

## ツールと能力

| 用語 | 一行説明 |
|---|---|
| **Tool（ツール）** | Agent が呼び出せる関数で、例えばファイル読み込み、コマンド実行、Web 検索など。各ツールは Schema（パラメータ定義）を持っています |
| **Tool Schema** | ツールのパラメータ定義で、このツールがどんなパラメータを受け取り、どんな型かをモデルに伝えます。モデルは Schema に従って呼び出しを組み立てます |
| **MCP（Model Context Protocol）** | モデルコンテキストプロトコル。標準インターフェース群で、Agent が外部ツールサーバーに接続できるようにします。dsh では `dsh-mcp-client` プラグインでサポートします |
| **MCP Server** | ツール群を提供する外部サービスです。例えば Firecrawl（Web スクレイピング）、GitHub（リポジトリ操作）など。dsh が接続すれば Agent がそれらのツールを使えるようになります |
| **Skill（スキル）** | モデル向けに書かれた指示で、「この種類のタスクに遭遇したらこの手順で進め」と伝えます。ワークスペースまたはユーザーディレクトリに保存され、モデルはオンデマンドでロードします |
| **Subagent（サブエージェント）** | メインエージェントがサブタスクのために派遣する独立した Agent で、完了したら結果を返します。2 つのモード：subagent（履歴なし）、subagent_fork（履歴あり） |
| **Workflow（ワークフロー）** | 複数ステップのオーケストレーションで、複数のタスクを順次または分岐でつなぎます。単一の固定ルーティンには Skill、複数ステップの連鎖には Workflow を使います |
| **Provider（プロバイダー）** | モデル API を提供するサービス、例えば DeepSeek、OpenAI、Anthropic。dsh は Model Adapter 経由で異なる Provider に接続します |

## セキュリティ

| 用語 | 一行説明 |
|---|---|
| **Sandbox（サンドボックス）** | Agent がアクセスできるファイルやリソースを制限する隔離メカニズム。OS カーネルレベルで、JS 判定ではないためモデルは回避できません |
| **Permission（権限）** | 三段階：read-only（読み取り専用）、workspace-write（デフォルト、ワークスペースのみ書き込み可）、danger-full-access（制限なし） |
| **Approval（承認）** | Agent が権限を超えた操作をしたいとき、ポップアップで確認してきます。1 回許可は 1 回限りで、永続的な許可ではありません |
| **Write-only（書き込み専用）** | API Key の保存方式。保存後はインターフェースに平文が表示されず、マスク済みの識別子のみ表示されます。平文はローカルの `.credentials.yaml` にのみ存在します |

## モデル

| 用語 | 一行説明 |
|---|---|
| **Model Adapter（モデルアダプタ）** | 異なるモデルプロバイダーの API を dsh 内部の標準インターフェースに統一するプラグインです。モデル切替 = アダプタ切替で、他のコード変更は不要です |
| **LLM（大規模言語モデル）** | 思考とテキスト生成を担う中核です。dsh 自体はモデルを持たず、スケジューリング（オーケストレーション）のみ行います |
| **KV Cache（キー値キャッシュ）** | 推論時に既計算のプレフィックスをキャッシュし、以降同じプレフィックスのリクエストは再計算なしで再利用します。ヒット部分は通常価格より遥かに安く課金されます |
| **Context Window（コンテキストウィンドウ）** | モデルが一度に処理できる最大トークン数です。これを超えた分はモデルに送られず、「忘却」と等価です |
| **Token** | モデルがテキストを処理する基本単位で、中国語は約 1 字 = 1.5 token、英語は約 4 文字 = 1 token。課金とコンテキスト制限はいずれも token 単位で計算されます |
