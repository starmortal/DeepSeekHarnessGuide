## Objetivo del capítulo

Este capítulo no tiene comandos ni entornos que configurar. Aclara tres cosas: **qué es dsh, qué puede hacer y en qué se diferencia de un modelo o de herramientas como Claude Code**. Al terminar estarás listo para instalarlo en CH 03.

## Qué es dsh

En una línea: dsh es el framework de ejecución de Agent que DeepSeek open-sourceó el 13 de agosto de 2026. El nombre del comando es `dsh`, el nombre completo es DeepSeek Harness, la licencia es MIT y el posicionamiento oficial es developer preview.

La página de inicio lo dice en una sola línea — **Everything is a plugin**. La ecuación oficial:

> Agent = Model + Harness

En palabras simples: **el modelo piensa, el Harness trabaja.** Un modelo solo genera texto; Harness es lo que permite a un modelo leer archivos, ejecutar comandos, llamar a APIs, gestionar el contexto y planificar — conecta el modelo con el mundo real para que las tareas realmente se terminen.

## No lo confundas con

El error más común: tratar dsh como "un asistente de programación con IA".

**No lo es.** Claude Code, Codex — esos son asistentes de programación. Son productos terminados: herramientas, Skills, sesiones y sandbox están todos envueltos en una sola carcasa; la pared no se puede tirar, la disposición no se puede cambiar. dsh es un "sustrato de ejecución": programar es solo una combinación preestablecida, y puedes ensamblar completamente Agents sin relación con la programación.

Otro error: **dsh no es un modelo.** DeepSeek V4 flash (y la versión con visión V4 flash vision exp) — esos son modelos. dsh es la "capa de sistema operativo" que permite al modelo trabajar; no son lo mismo. Y en dsh, el modelo DeepSeek es solo el plugin predeterminado preinstalado — puedes cambiarlo por cualquier otro modelo.

## Cuatro palabras clave para conocerlo

**1. Todo es un plugin.** Modelo, herramientas, Skill, sesión, sandbox, almacenamiento, bucle, scheduler, UI — cada capacidad es un plugin (un bloque Lego), y puedes intercambiarlos, eliminarlos o añadirlos.

**2. La capa base es Cordis.** El núcleo Cordis gestiona el montaje, desmontaje y dependencias de los plugins. Los plugins se coordinan a través de servicios y eventos; cualquiera puede unirse, nadie tiene privilegios.

**3. Cada ejecución es trazable.** Todo lo que el modelo ve se escribe en un registro de sesión append-only: prompts del sistema, razonamiento, llamadas a herramientas y sus resultados, programación de subagentes, cada inyección de contexto. Navega por fuente en la vista Trajectory. Esto significa observable, auditable, reproducible — importante para investigación y producción.

**4. Cuatro modos de ejecución.** No te asustes por los nombres: no son cuatro motores sino cuatro plantillas de combinación de plugins preestablecidas — y puedes definir nuevas tú mismo:

![Cuatro modos de ejecución (ilustración)](/assets/part01/runtime-modes.svg)

- **Estándar**: el predeterminado para nuevos usuarios. Capacidades completas de Agent de código: edición de archivos, Shell, búsqueda de archivos/web, Skills, planes, objetivos, subagentes, workflows. Listo para usar de inmediato.
- **Code**: todo lo que tiene Estándar, además de herramientas expuestas mediante el SDK para que el modelo pueda escribir un programa TypeScript y orquestar múltiples pasos en una sola pasada. Cinco llamadas de modelo tipo "leer, buscar, filtrar, llamadas paralelas" pueden potencialmente colapsar en una ejecución de programa, ahorrando tokens y reduciendo latencia. El costo es la dependencia de la capacidad de código del modelo y una depuración más difícil; los principiantes deberían mantenerse lejos.
- **Minimal**: solo bash persistente + un editor de archivos. No es para desarrollo diario — es para ejecutar benchmarks de "Agent desnudo" para comparar la fuerza bruta de dos modelos sin herramientas sofisticadas.
- **Creator**: todo lo que tiene Estándar, más una cosa extra: puede inspeccionar el entorno Cordis en ejecución, experimentar con plugins en memoria, crear nuevos Agents y plugins, e incluso modificarse a sí mismo.

Los recién llegados deberían elegir Estándar. Cambia a Code cuando enfrentes llamadas de herramientas repetitivas pesadas y quieras comprimir las idas y vueltas. No uses Minimal para trabajo diario — le faltan piezas y te hará cuestionar tus decisiones de vida.

## Para quién es, y para quién no

Estas líneas son la evaluación de la comunidad basada en pruebas reales, no la posición oficial.

**Adecuado para**: desarrolladores y entusiastas de IA que quieren estudiar el mecanismo de plugins y ensamblar su propio entorno de ejecución; equipos que necesitan embeber capacidades de Agent en sus propios sistemas — el modelo de plugins es un sustrato listo para usar; investigadores de Agent — la función de trajectory es naturalmente adecuada para experimentos reproducibles; usuarios individuales que quieren usar Agents listos para usar en tareas diarias — los plugins de la comunidad ya cubren reconocimiento de imágenes, lectura/escritura de documentos Office (Excel/Word/PPT), automatización de navegador, equipos multi-Agent, etc. Los huecos que el equipo oficial no ha llenado, la comunidad los ha cerrado en su mayoría.

**Piénsalo dos veces si**: no quieres trastear con plugins en absoluto y solo quieres doble-clic-y-listo — dsh todavía no llega ahí. El valor predeterminado oficial solo carga el conjunto mínimo de herramientas (Shell, lectura/escritura de archivos, edición de código, búsqueda web); para reconocimiento de imágenes, Office y automatización de navegador tienes que instalar plugins tú mismo. Y el equipo oficial advierte explícitamente que esto es un developer preview con cambios disruptivos, actualizado a diario. Si quieres tranquilidad, espera a que las capacidades predeterminadas se desarrollen y el ecosistema se asiente.
