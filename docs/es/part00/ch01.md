## Objetivo del capítulo

Este capítulo no te enseña ninguna operación. Te dice solo dos cosas: cómo leer este libro, y a qué ritmo aprender. Primero elige una ruta de aprendizaje que te encaje, y luego sigue el plan de tres días: con un mapa claro, no te perderás.

## Tres rutas de lectura

Echa un vistazo a este diagrama primero, para hacerte una idea aproximada:

![Tres rutas de lectura (ilustración)](/assets/part00/reading-paths.svg)

### Ruta 1: lectura secuencial para principiantes (recomendada)

**Para quién es**: primera vez con dsh, nunca has ejecutado un Agent.

**Cómo leerlo**: empieza por CH 00 y avanza capítulo a capítulo. Termina PART 01 (CH 02–07) de un tirón — pasa primero la barrera del "ya funciona". Luego lee CH 09 "Subsistemas centrales y el flujo de un mensaje", y solo después vuelve a CH 08 y CH 10. Tendrás la sensación de "ahora lo entiendo".

**Por qué este orden**: los primeros capítulos están organizados en torno a tareas reales; cada paso se apoya exactamente donde lo necesita el siguiente. Saltarse pasos atasca, y desatascar después cuesta más.

### Ruta 2: salto directo por escenario

**Para quién es**: ya sabes qué quieres hacer, no quieres leer desde el principio.

**Cómo leerlo**: salta directo con esta tabla:

| Tu objetivo | Lee esto |
| --- | --- |
| Solo quiero ponerlo en marcha rápido | CH 03 → 04 → 05 |
| Quiero entender la arquitectura antes de tocar nada | CH 08 → 10 |
| Quiero conectarme al ecosistema MCP | CH 12 |
| Quiero encontrar plugins ya hechos e instalarlos | CH 12 → 17 |
| Quiero que el Agent trabaje en horarios programados | CH 15 |
| Quiero desplegarlo en local | CH 16 |
| Quiero usar dsh para hacer PPT / informes / vídeos | CH 25 → 26 |
| Quiero desarrollar mis propios plugins | CH 18 → 20 → 21 |
| Quiero llevarlo a producción | CH 27 → 28 → 29 |

Los capítulos que saltes con "salto por escenario" puedes revisitarlos si te atascas — no pasa nada. Nadie termina a la primera.

### Ruta 3: profundizar bajo demanda

**Para quién es**: ya puedes ejecutar dsh, lo usas como libro de referencia.

**Cómo leerlo**: cuando aparezca un problema, mira el índice y salta al capítulo correspondiente, combinado con los apéndices. Apéndice A (Glosario), Apéndice B (Chuleta de comandos), Apéndice C (Índice de documentación oficial) son el trío diario. CH 07 (Chuleta de troubleshooting) merece guardarlo aparte.

**Característica**: no hace falta leer en orden; cuando un capítulo te atasque, ábrelo.

## Plan de aprendizaje de tres días

Si quieres recorrer dsh de principio a fin en un bloque concentrado, el plan de tres días de abajo puede seguirse tal cual. Cada día está dimensionado para "leer mientras se hace" — no es pura lectura de documento.

### Día 1: ponerlo en marcha, construir intuición

**Objetivo**: instalar dsh, ponerlo en marcha y saber qué puede hacer.

**Leer**: CH 00 → CH 07 (PART 00 + PART 01)

**Hacer**:
1. CH 03: instala Node.js y dsh, lanza la Web UI
2. CH 04: familiarízate con la interfaz — elige workspace, modelo, envía el primer mensaje
3. CH 05: ejecuta una tarea headless una vez, experimenta "trabaja sin que nadie mire"
4. CH 06: conecta un modelo de terceros (por ejemplo un modelo local o la API de otro proveedor)
5. CH 07: cuando aparezca un error, recorre el flujo de troubleshooting

**Al final deberías poder**: abrir dsh, enviar mensajes, ejecutar headless, conectar un modelo de terceros, leer errores básicos.

### Día 2: entender el esqueleto, montar capacidades

**Objetivo**: entender qué significa realmente "everything is a plugin", y cablear las capacidades habituales.

**Leer**: CH 08 → CH 16 (PART 02 + PART 03)

**Hacer**:
1. CH 08–10: entiende el árbol de plugins, el flujo de mensajes, las sesiones y la trajectory — estos tres son teoría, sin código, solo comprensión
2. CH 11: entiende el pipeline de llamadas a herramientas y las aprobaciones de permisos
3. CH 12: conecta un servidor MCP (p. ej. Firecrawl) para que el Agent pueda capturar páginas web
4. CH 13: prueba un subagent, experimenta "delegar trabajo a otros"
5. CH 14: instala un Skill (p. ej. AIHOT) para que el Agent use capacidades ya hechas
6. CH 15: configura una tarea programada para que el Agent se ejecute automáticamente cada día
7. CH 16: conecta un modelo local, experimenta "úsalo sin pagar"

**Al final deberías poder**: explicar la arquitectura de plugins de dsh, conectar MCP, usar subagents, instalar Skills, configurar tareas programadas, y conectar un modelo local.

### Día 3: desarrollar plugins, llevarlo a producción

**Objetivo**: escribir un plugin propio, y saber cómo desplegarlo y operarlo.

**Leer**: CH 17 → CH 23 (PART 04) + CH 27 → CH 29 (PART 06)

**Hacer**:
1. CH 17: aprende a instalar y gestionar plugins
2. CH 18–21: escribe cuatro plugins siguiendo el libro — mínimo, servicio, herramienta, hook — y ponlos en marcha
3. CH 22: escribe un plugin de UI y añade una pestaña en la página de ajustes
4. CH 23: entiende los adaptadores de modelo (lectura opcional; sáltalo si no vas a desarrollar plugins)
5. CH 27: usa Docker para desplegar dsh en un servidor, asocia un dominio y configura HTTPS
6. CH 28: repasa la checklist de seguridad, confirma permisos y credenciales
7. CH 29: aprende a leer trajectories, gestionar el contexto, controlar el coste

**Al final deberías poder**: escribir un plugin que funcione, desplegarlo en un servidor, y gestionar seguridad y coste.

## Punto de partida común de las tres rutas

Sin importar qué ruta tomes, dedica primero diez minutos a CH 00. Son solo tres intuiciones, sin operaciones, y sin embargo es la base de todo lo que viene después: **Agent = Model + Harness, everything is a plugin, por qué ahora**.
